# Completio - Agent Guide

## Project

**Completio** is an AdonisJS + React/Inertia application for AI-powered text completion. The current codebase is still early-stage: the completion API is wired through an `AiService`, but the only provider implemented today is a stub handler.

## Tech Stack

| Layer | Technology |
| --- | --- |
| Runtime | **Node.js 24+** |
| Package manager | **npm** (`package-lock.json` is present) |
| Backend framework | AdonisJS v7 |
| Frontend | React 19 + Inertia.js |
| Styling | Tailwind CSS v4 + DaisyUI v5 |
| ORM | Lucid |
| Database | SQLite by default; optional MySQL config is scaffolded |
| Validation | Vine |
| API client | Tuyau |
| Notifications | Sonner |
| Tests | Japa |

## Common Commands

npm install

## Architecture

### Backend Layout

```text
app/
├── common/interfaces/        # shared TS interfaces, including AiHandler
├── controllers/             # HTTP controllers
│   ├── completion_controller.ts
│   └── user/                # signup / login / logout
├── middleware/              # auth, guest, inertia, silent auth
├── models/                  # Lucid models
├── services/                # application services
│   ├── ai_service.ts
│   └── handlers/            # AI provider implementations
├── transformers/            # model serializers for Inertia shared props
└── validators/              # Vine validators

database/
├── migrations/              # source of truth for schema changes
├── schema.ts                # autogenerated from migrations; do not edit
└── schema_rules.ts

inertia/
├── app.tsx                  # client entrypoint
├── ssr.tsx                  # SSR entrypoint
├── client.ts                # Tuyau client setup
├── layouts/
└── pages/

providers/
└── api_provider.ts          # adds ctx.serialize() helper
```

### Completion Flow

```text
POST /api/complete
  -> CompletionController.complete
  -> completionValidator
  -> AiService.complete
  -> current handler: StubHandler
```

- `app/common/interfaces/ai_handler.ts` defines the provider contract.
- `app/services/ai_service.ts` is the facade used by controllers.
- `app/services/handlers/stub_handler.ts` is placeholder logic and should be replaced or extended when adding a real AI provider.

### Auth Flow

- Session-based auth uses the `web` guard from `config/auth.ts`.
- Signup and login controllers live under `app/controllers/user/`.
- Auth routes are grouped under `/api/auth/...` in `start/routes.ts`.
- Shared authenticated user data is exposed to Inertia via `app/middleware/inertia_middleware.ts` and `app/transformers/user_transformer.ts`.

## Routing

Routes are defined in `start/routes.ts`.

- `POST /api/complete`
- `GET /api/auth/signup`
- `POST /api/auth/signup`
- `GET /api/auth/login`
- `POST /api/auth/login`
- `POST /api/logout`
- `GET /` renders the `home` Inertia page

When changing routes, keep the generated Tuyau registry and Inertia route usage in mind.

## Frontend Conventions

- Inertia pages live in `inertia/pages/`.
- The shared page shell is `inertia/layouts/default.tsx`.
- The app is wrapped with `TuyauProvider`; prefer the configured client in `inertia/client.ts` over ad hoc network code.
- Forms currently use `@adonisjs/inertia/react` `Form` components.
- Global toast handling is already wired with Sonner in the default layout.
- Styling is Tailwind v4 with DaisyUI; the default theme is configured in `inertia/css/app.css`.

## Data And Persistence

- SQLite is the active default connection and stores data in `tmp/db.sqlite3`.
- MySQL config exists in `config/database.ts` but is commented out.
- Session storage is configurable via `SESSION_DRIVER`; cookie and database stores are configured.
- Redis is configured in `config/redis.ts` for cases where the app starts using it.

## Generated And Sensitive Files

- Do not manually edit `database/schema.ts`; regenerate it through Adonis migration tooling.
- `@generated/*` imports come from Adonis/Tuyau codegen.
- `.env.example` documents required environment variables; real secrets must stay out of version control.

## Import Conventions

Path aliases are defined in `package.json` `imports`.

- Prefer `#services/*`, `#models/*`, `#validators/*`, `#controllers/*`, `#database/*`, and similar aliases.
- Prefer `~/...` aliases inside the `inertia/` frontend code.
- Avoid long relative imports across top-level directories.

## Testing

- Japa is configured in `adonisrc.ts` with `unit`, `functional`, and `browser` suites.
- Test bootstrap lives in `tests/bootstrap.ts`.
- Browser test helpers for auth and session are already configured.
- There are currently no substantive test files in `tests/` beyond bootstrap, so new features may need fresh coverage.

## Practical Guidance For Agents

- Use `npm` and `node ace ...` commands, not Bun.
- Check existing controllers, validators, and middleware before adding new abstractions; the codebase is still small.
- Keep the completion system provider-agnostic by extending `AiHandler` implementations instead of coupling controllers to a specific SDK.
- Preserve Inertia shared props behavior when changing auth or flash handling.
- Prefer small changes that fit the current lightweight structure rather than adding heavy architecture early.
